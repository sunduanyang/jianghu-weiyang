# Battle UI transition and animation events

The stable host API is `new OriginalUIFlow(hudRootTransform, uiSource, relayTimeScale)` followed by `SetState(networkState, paused)`. Scope is original network states 2 through 6 and local None/Paused states 0/10. Call SetState when the host changes state; the class owns no independent phase timer.

`UITransitionAnimator` is the literal original type; `hz` is a separate original time-event relay. This recovery restores the former in `OriginalUITransitionAnimator.cs` and forwards the latter's unchanged float callback from the same Animator GameObject through its `RelayTimeScale` event method.

## Source flow

The actual CanvasAndCamera.networkedPairs and local paused pair are read from the supplied UI source JSON. The flow does not synthesize screen lists.

- `CanvasAndCamera.ccs` (`0x3415ac8`) closes the old network pair and opens the new pair. `ccx` (`0x3415c94`) calls the original transition Exit(false) if a transition exists and its host is active. With no transition, it directly disables that pair's listed screens. `ccy` (`0x3415e60`) enables listed new screens and calls Enter. Only network 2→4 requests EnterDelayed; the actual state-4 pair has no transition, so this does not invent a Round enter trigger.
- `cct/ccz/cda` (`0x34167d8`, `0x34169ec`, `0x3416be0`) retain the network screens beneath local Paused. Entering Paused opens the original PausePanel pair without closing network screens. Leaving Paused starts its exit and reopens the current network pair.
- Old and new transition screens can therefore coexist while the old screen exits. There is no per-frame blanket deactivation of MainContainer children.
- Standalone bootstrap directly hides source menu screens before the first battle state; this is a local-host entry adaptation, outside the requested menu workflow.

The literal transition methods are restored from ARM64 and the completed `native-transition-c` export:

- Enter (`0x36b7448`) cancels the pending exit coroutine, activates its serialized root if needed, then calls Animator.SetTrigger with Enter or EnterDelayed. It does not force Animator.Play, rebind the Animator, or replace its state graph.
- Exit (`0x36b7524`) immediately hides the root only for its immediate flag. Otherwise it sets Exit only when Animator.isActiveAndEnabled, and starts its exit coroutine when the component host is active in the hierarchy.
- The iterator ga.MoveNext (`0x36b7ff8`) always yields null once, then yields null while the current layer-0 Animator state's normalized time is less than 1. It then hides the serialized root and clears the pending coroutine. It does not use a guessed clip-length timer.
- OnDisable (`0x36b7ea8`) stops and clears the pending exit coroutine. ShowSub and HideSub retain their original GameObject argument behavior.

## Original assets and event dispatch

`scripts/export_bloody_ui_flow.py` produces `Runtime/Resources/OriginalUIFlowSource.json` from MainScene. The battle/paused scope contains **65 Animators**, of which 55 have controllers; **11 legacy Animation components**, **11 UITransitionAnimator components**, **5 enabled hz relay hosts**, and **35 reachable source clips**. Ten controllerless Animators are the original Animancer-driven verdict popup hosts.

The runtime restores each source Animator's enabled flag, update mode and culling mode, and each source legacy Animation's enabled/autoplay/physics settings. Existing original controllers and clips are retained. Before the later target-version script-reference preparation, all 45 controller/override/clip assets in this dependency graph were present in the generated project and their SHA-256 values matched the original exported files. The preparation step now remaps animation script PPtr references from old TMP/UGUI/Light2D DLL scripts to their Unity 6000.4 equivalents. Prepared files therefore need not retain their source SHA; the original curve keys, parameters and events must remain unchanged. Original copies under the recovery source Resources remain byte-identical. No alternate controller or resampled curve is generated.

All events in this reachable clip graph are RelayTimeScale (46 events across seven clips); each is preserved in its original .anim file, including the two different values at RoundOrMatchEnd_Enter time 2. The Animator sends them through the runtime receiver. The original normal/unscaled update modes govern event advancement and ordering; the host must **disable its manual timeline replay** when this flow is connected. Keep the separate native hy.dxl phase-3/4 reset to scale 1. The original relay callback itself does not filter on Paused.

The raw UI contains unrelated duplicate decorative hierarchy names. All **76 source-bound animation/transition nodes are unique**. The node inventory tolerates unbound duplicate names rather than failing during initialization.

## Host integration details

Replace the host's blanket screen-switch loop with `flow.SetState(value, isPaused)`. Before the first SetState for state 5 or 6, call `flow.ActivateVerdict(isMatchEnd, isWin, gameMode, resultContext)` once. Keep the existing bars, localized text, button actions and explicit human PlayerControls visibility policy. The source state-4 uiScreens list is Round plus TopBar_InGame; PlayerControls is controlled separately.

Countdown remains active during its original exit animation after state 4 begins. Its Fight text should follow countdown remaining <= 0 while that parent is exiting, without an additional `state == 3` visibility condition. The parent screen's actual exit controls its final visibility.

Call Dispose when disposing the HUD. Rendering, input and phase clocks remain owned by their existing systems; the flow forwards only the original AnimationEvent floats to the supplied callback.

## Verdict popup recovery

`OriginalUIPopups.cs` and `OriginalUIPopupDriver.cs` restore the six native popup classes on all ten mounted hosts: LostPopup (five hosts including RoundEnd and OpponentForfeited), WonPopupRandom, WonPopupCampaign, WonPopupSurvival, WonPopupRanked and LostPopupRanked. `scripts/export_bloody_ui_popups.py` exports their exact eleven original clips, nine audio clips and thirteen AudioObjects, including the RoundEndView/MatchEndView death sounds. No curve is rebuilt or resampled. All six animation events have null object-reference arguments and are received by the recovered driver. The five event function names are PlayWinningsSFX, PlayHeaderSFX, PlayBadgeFillHaptic, PlayRankUpHaptic and PlayNewItemsInShopHaptic.

Call `ActivateVerdict` before `SetState` on the state-5/6 edge, and do not repeat selection for a pause-only change. This follows ShowRoundEndPopup (`0x36b5730`) and ShowMatchEndPopup (`0x36b2c2c`): disable Popups, disable old popup children, select the matching child with activeSelf=true, and immediately play deathWon/deathLost. **Leave Popups disabled**. The original RoundOrMatchEnd_Enter curve enables Popups at **2.5 seconds**, which starts the selected popup's OnEnable, original open clip and openSFX at that point. Early container activation would consume audio RNG and animate the verdict too soon. The optional matchEndReason parameter selects the source forfeited popup for reasons 1/2 outside ranked mode; its mounted FireEventOnEnable's two SetActive calls use remapped clone-node references. Localized round-winner and forfeited-name text remains the host's text service responsibility.

The Playable driver retains the source Animator update modes individually: the random/friendly win, ranked win/loss and campaign win use UnscaledTime; the other six hosts use Normal. Native Animancer CreateOutput (`0x332c3b0`) calls AnimationPlayableUtilities.Play (`0x6a59b78`), which calls InternalSyncUpdateAndTimeMode (`0x6a5c210`). Repeated Play of the same clip retains its current time; native layer Play (`0x333c3a0`) and state Play (`0x334eb1c`) do not reset its time. The source DisableAction is Stop (0) on every popup. The recovery stops/reset states on disable, cancels the popup coroutine, and kills its active local star/bar tweens.

Campaign restores the 0.5-real-second opening wait, each 0.05-second unscaled OutBack star scale tween and 0.15-second spacing, winnings/no-winnings jump, new-items jump, reward bonus path and rewarded-video failure restoring the button. Survival restores wave/reward setup and bonus behavior. Ranked restores cached/fallback setup, first-result-only notification, one-second initial real-time wait, eight-second timeout, source result arrival behavior, rank/derank ordering, both parallel 0.8-second unscaled OutCubic slider/counter tweens, source minimum fill changes (win 0.02/loss 0.03), badge changes, and all event haptic arguments. In particular PlayRankUpHaptic is `(1, 2, 2.5)` in the native method, and the serialized loss rankDown clip is not played by the native loss iterator.

`OriginalUIPopupResult` supplies actual campaign, wallet, ranking and advertising results/callbacks. Friendly mode 5 and ordinary RoundEnd need no result context. Campaign/Survival/Ranked services have not been invented by this combat port. For asynchronous ranked replies, prepare the rank-configuration context before activation, then call the selected driver's `ReceiveRankedResult(result)`; subsequent replies are ignored as in native dpw/dni. Advertising callbacks accept success and failure actions. Required wallet/new-item callbacks fail explicitly if absent rather than silently displaying invented rewards. `flow.Popups.HapticRequested` forwards the source haptic event arguments to a platform adapter.

`OriginalUIAudio.cs` restores bg.PlaySound (`0x3411e0c`): validate AudioSource.enabled and AudioObject, integer clip selection, then volume and pitch float draws, additive volume offset, loop setting and Play/PlayOneShot. It shares Unity's global random stream and does not call VoiceSFX's frame-seeded random reset. `scripts/verify_bloody_ui_audio.py` executes the original valid/disabled/empty audio paths and compares the actual C# calls/settings through the loop setter: **270 checks passed** across 48 source configurations. Engine audio scheduling and Random's underlying implementation are outside these bounded hooks.

`scripts/verify_bloody_ui_popup_math.py` executes the original NudgeFill and both ranked tween prefixes to the DOTween Sequence call. It compiles the actual shipped OriginalUIPopupMath class: **2,580 checks passed, maximum error 0**. `scripts/verify_bloody_ui_popups.py` checks exact clip/audio bytes, resolved scene references, original curve target paths and event receiver methods. The original random-win clip itself contains one unbound m_IsActive curve for `Popup/Header`; that node is absent in the original MainScene. This original empty binding is retained and is not an introduced clone failure. Report: `output/bloody-full-port-20261028/ai-check/ui/popup-assets-verification.json`.

Full Unity Playable event scheduling, local tween update phase, all service-backed popup branches and rendered UI parity still require engine/reference capture. Static binding checks and numeric/native-call parity do not establish whole-UI equivalence.

## CountdownView

`OriginalCountdownView.Attach(hudRoot, uiSource, () => host.CountdownRemaining)` binds the actual CountdownView host, its two original TMP texts and UISFX default AudioSource. Attach it after OriginalUIFlow has hidden bootstrap screens, and remove the host's per-frame countdown/fight text and active-state writes. Keep the original Countdown parent controller and transition driver enabled. There is no local state-number gate: the view continues updating while its original parent exits.

Awake (`0x368c2bc`) caches the countdown text's local XY once. OnEnable (`0x368c2f0`) hides both text GameObjects and resets lastSecond to -1. Update (`0x368c34c`) changes content only when `max(0, CeilToInt(remaining))` changes; original ARM64 uses frintp/fcvtps, despite the decompiler's incorrect truncating-int expression. For a positive second it activates the number, hides Fight, writes the integer text, sets alpha 1, starts DOFade(0,0.5) with InCirc, resets local position to cached XY/Z0, and starts relative DOLocalMoveY(-25,0.5) with InCirc. At zero it hides the number, activates Fight with alpha 1, resets Fight to the same cached XY/Z0, and starts relative DOLocalMoveY(+50,1) with OutCirc. All these tweens use independent/unscaled updates and auto-kill. There is no source OnDisable tween kill; a scheduler on the active HUD root continues updating an inactive target until its tween finishes.

The view does not manually hide Fight at a guessed time. The unchanged Countdown_Exit clip has stop time **0.5833333 seconds** and alpha keys at 0=1, 0.33333334=1, 0.5≈0 and 0.5833333=0. The original transition subsequently closes its root when Animator.normalizedTime reaches 1. Source parent-animation timing decides the visible window.

The two mounted AudioObjects are exported with their two original clips by `scripts/export_bloody_countdown.py`: Seconds has volume 1/pitch 1 and Fight volume 1.5/pitch 1, both one-shot. Countdown raises df.UI.RaiseUISFX with source type 0; literal UISFX.dov (`0x36b7bf8`) first stops audioSourceDefault, then chooses Default (Transitions only for type 1), and calls bg.PlaySound. This order is preserved, including the integer clip draw and both fixed-range float Random.Range calls. No extra AudioSource or seeded random stream is introduced.

`scripts/verify_bloody_countdown.py` runs original CountdownView OnEnable/Update and DOTween EaseManager InCirc/OutCirc ARM64 instructions under bounded Unity hooks. It compiles the actual shipped countdown source against lifecycle/graphics shims and checks **1,854 assertions**: 84 remaining/previous-second combinations, four initial active-state combinations, 202 native ease samples, output text/visibility/alpha/position, tween destinations/duration/ease, UI sound choice, Stop-before-sound count, and inactive-target tween completion. All pass. Report: `output/bloody-full-port-20261028/ai-check/ui/native-countdown-comparison.txt`. Actual Unity update order, TMP rendering, CanvasGroup exit and engine audio/random advancement remain reference-capture checks.
