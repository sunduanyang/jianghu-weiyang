# 江湖未央 · Unity 版

Unity 6000.6.7f1 原生 Windows 客户端，项目目录是 `JianghuUnity/`。安装 Python 3.12+，在 Unity Hub 添加该目录，打开 `Assets/Scenes/Jianghu.unity`，按播放即可运行。默认安装路径也可双击项目根目录的 **用Unity打开.bat**。Python 不在 PATH 时，在启动编辑器前设置 `JIANGHU_PYTHON` 为其完整路径。

公开源码已包含美术、地图纹理和 `.meta` 文件；不包含作者存档、模型、Unity 缓存、Windows 成品或 Python 二进制运行时。无需重新生成资源即可开始修改。**启动Unity版.bat** 用于运行自己构建出的 Windows 程序；如果构建时选择附带 Python，成品无需另外安装 Python。

Unity 负责原生窗口、交互、舆图、城内地图和皮影关节动画；原有 Python 规则引擎作为随游戏启停的本机进程运行。没有嵌入网页，也没有重写一套简化社会规则。运行不需要联网或下载 Unity 商店插件。

人物战斗页显示十项独立能力以及气血、气力、架势和体格。旧武学与功法系统已移除，原人物数据在新版读档时清理；不折算旧武学和功法。改动与验收见 [人物战斗属性](../COMBAT_ATTRIBUTES_VALIDATION.md)。

新的九品武学按门中／社会品阶自动分配：14派共126门，各有2至3项能力加成。战斗页可查看已掌握功法及各派完整目录，门派页和人物档案同步展示；规则和加成表见 [门派九品武学](../MARTIAL_NINE_GRADES_DESIGN.md)。

行囊默认打开装备页，只设主手、副手、护甲三个槽位，支持穿卸、修补、替换对比与生效状态。双手兵器暂时停用盾牌，换回单手兵器后自动恢复；停用装备不提供防护，也不产生战斗磨损。旧佩饰和器具槽位读档时解除，物品继续保留。见 [装备系统验证](../EQUIPMENT_SYSTEM_VALIDATION.md)。

行囊与货栈的物品筛选统一为一排「类别下拉、名称搜索、重置」。物品按类别及品级自动排列，连续网格合并显示同类物品；品级保留在卡片和详情中，不再单独筛选或选择排序。装备管理集中在装备页。

## 已接入内容

界面按太吾绘卷的思路分三层：天下／城中地图永远在底层；人物卷、江湖卷、系统三张卷轴全屏打开；对话与切磋叠在最上面。从哪里打开就叠在哪里之上，卷轴右上角的返回按钮和 Esc 都是「返回上一层」，在地图上按 Esc 打开系统。导航逻辑集中在 `UiNav.cs`。

- **点人**：点击左侧人物头像、城中人物或地点中的人，打开人物交互界面。左右显示主角与所选人物，中央有六个分类：交谈（夸奖、羞辱、赠送礼物）、比武（切磋）、修习（请教）、亲近（知心而交、共结连理、义结金兰）、敌对（偷窃、抢夺、袭击）、互动（交易）。12项均可实际结算：点击查看条件和消耗，再确认；赠礼和交易选择真实行囊物品，请教可获秘籍，亲近会登记知交、婚姻或结义关系，敌对交手产生伤势、恩怨和声望损失。需要先创建主角、暂停世界并到达对方所在地区。支持点击、F1—F6 和 Q/E 切换，点击「道别」或按 Esc 返回；详情中的 Esc 先返回分类。规则、条件和验证见 [人物交互](../CHARACTER_INTERACTION_VALIDATION.md)。
- **人物卷**：看自己与看任何人是同一张卷、同一套标签——概览（此刻与打算）、品性（身份品阶、升降、本领、心性）、武学、行囊、人情（家计乡里、关系、门中）、生平。左栏可切换「我的人物」与近期看过的人，标签保持不变；赠物明确从主角自己的行囊取物。
- **交谈与说服**：旧交谈能力融入上述人物交互界面。「交谈」增加闲叙、和解，「互动」增加求助、引荐、接济回报；商谈话题选择器保留包括结义在内的原六种请求。中央可切换交谈记录、五种性格说服、人情与引荐；被拒后直接选择刚正、仁善、中庸、叛逆、唯我台词，NPC重新决定并实际结算。人物卡可直接查看行囊和武学。商谈需要启用本地模型，原12项即时事项继续依规则运行；详见 [交谈整合验证](../INTEGRATED_CONVERSATION_VALIDATION.md)。
- **江湖卷**：势力（政权／门派／乡里）、市井（货栈、制药、市井供需）、年谱。
- **系统**（Esc 或顶栏右侧）：存档、本地模型、皮影衣橱（调试用）。
- **底栏**：左边「人物／行囊／武学」打开主角人物卷的对应标签，右边「势力／市井／年谱」打开江湖卷；世界推演并入月轮旁的「推演」按钮。
- **每月顺序**：主角先行动，人物互动只消耗玩家行动力，可在同月重复执行，不检查或占用NPC时间。「结束本月」后，NPC按自己的完整预算独立行动，再开始下月。旧存档会自动释放玩家互动占用的NPC时间，保留NPC自己的日程、历史事件和财物；重复读档不会重复返还时间。规则与验证见 [互动行动力规则](../INTERACTION_AP_ONLY_VALIDATION.md)。

人物导航的验收见 [人物导航与分页归属](../CHARACTER_NAVIGATION_VALIDATION.md)。PR #7 的整合保留了可搜索下拉选项、筛选重置、模型与存档分区、状态提示及返回时的物品筛选和事件详情；城中「返回切磋」会主动加载存档战局，重启后无需先打开武学页。当前入口、回归与默认构建见 [PR #7 整合验收](../PR7_INTEGRATION_VALIDATION.md)。

## 存档

天下地图中，双击主角所在区域直接进入该区舆图；双击其他区域弹出移动确认，列出路线、全程精力及本月可抵达的区域。可从当前区域任意位置出发，远行只消耗精力，不收盘缠。确认后沿真实相邻路线逐区前进，下一段精力不足时提示「精力不足，点击过月」；点击「过月」推进一个月并继续原目的地，抵达目标后进入舆图。行程不会自动过月；取消或按 Esc 停止后续行程，保留已抵达位置和已花费精力。构建和检查见 [天下地图双击行旅验收](../WORLD_TRAVEL_VALIDATION.md)。

公开源码首次启动会创建新的800人世界，保存在 `%USERPROFILE%\AppData\LocalLow\JianghuStudio\江湖未央 Unity\Saves`。后续继续这个独立世界。原项目 `data/` 不会被 Unity 写入。作者本地保留的迁移快照只在本机使用，不随仓库公开。

「系统·存档」显示实际使用的完整数据库路径，也能打开存档目录。导入旧存档时用 SQLite 在线备份创建新副本；当前 Unity 世界和原始存档均保留。原世界在本次快照之后发生的新变化需重新导入。新世界同样另存文件。

首次运行默认关闭 AI，显式保存的启用设置在新会话保留。在 Unity 的「系统·本地模型」页启用后，可自动启动已安装的 Qwen3.5 4B Q4_K_M；也可先运行原项目的 **启动本地模型.bat**。两种入口共用 `.runtime/manifest.json`，NVIDIA 机器使用 CUDA，模型文件没有重复复制。原默认 llama.cpp 配置的 `qwen3:4b` 自动更新为 `qwen3.5:4b`，保留启用、队列和重复思考间隔等偏好；自定义端点与 Ollama 配置保留。规则快进始终跳过模型调用。

Windows 程序可选择附带私有 CPython 运行时，不安装系统服务。Unity 退出或结束播放会通知本次引擎保存并退出；引擎另监测父进程退出。它使用临时本机端口和每会话凭据，仅供当前 Unity 会话使用，不提供游戏网页。

本机的 Unity DX12 初始化曾出现原生崩溃，项目构建和启动入口已固定使用 Direct3D11。编辑器入口会自动打开主场景。

## 继续开发和构建

主要脚本位于 `Assets/Scripts/`：`JianghuApp.cs` 是界面入口，`WorldUI.cs` 管理双层地图和寻路，`Panels.cs` 管理玩法面板，`PaperRig.cs` 与 `PaperCast.cs` 驱动新皮影骨骼和外观，`GameClient.cs` 管理请求和进程。共享规则的源文件是仓库根目录的 `jianghu/`，`Assets/StreamingAssets/Backend/jianghu/` 是其同步副本。

修改共享规则后运行 `python unity/prepare.py --backend-only` 同步到 Unity 并一起提交。仅修改 C# 界面或场景时无需同步。`prepare.py` 不会默认复制本机存档；作者确需迁移本机旧档时可显式传入 `--include-local-save`，得到的数据库继续由 Git 忽略。

编辑器菜单 **江湖 / 构建 Windows 游戏** 默认生成 `unity/Build/Current/江湖未央.exe`。启动器优先按 `unity/Build/active-build.txt` 选择本地版本，以该文件的实际内容为准；只有未指定有效版本时才回退到 `Current`。这样可在旧窗口仍运行时构建新版，下次启动生效。也可关闭这个项目的编辑器后运行 `构建Unity版.ps1`；自定义 Unity 安装路径使用 `-EditorPath`。默认构建只同步规则，不重新生成美术。需要可独立运行的成品时，先执行 `python unity/prepare.py --bundle-python`，或给构建脚本传入 `-BundlePython`。

重生成资源需要 `python -m pip install -r requirements-dev.txt`，再执行 `python unity/prepare.py` 和 `python unity/bake_paper_cast.py`。`assembly-calibration.json` 保存成品图的身体比例参考；肩关节由躯干拆分件自身坐标确定，双臂采用自然空手姿态；`split-calibration-*.json` 标注右侧独立拆分件自身的肩肘腕髋膝踝接点、宽度、镜像和遮挡。`bake_split_cast.py` 将拆分部件放入游戏图集，逐件记录右侧原板来源区域和哈希；最终整身图仅用于比例和视觉对照。

`PaperCast.cs` 把每个上臂、前臂、大腿和小腿的两个源锚点映射到骨段；头、腰胯、手、脚及配件跟随对应骨点。`breadth` 校准正面拆分图到侧身装配的宽度。头像来自拆分头部，半身图来自同一批拆分件的静态装配；`PaperReference/` 仅供衣橱对照。运行时不使用整身图切割蒙皮。24套皮肤共用 `paper-rig.json` 的父子骨架，只保留 `walk` 一个循环。`bind` 是固定装配姿态，不是待机动作。行走采用双腿 IK、固定骨长、统一脚底地面和反向摆臂；停止时先混合行走权重再求解骨架。`walk-socket-overrides.json` 保存长袖等部件的源像素接点修正。手持物品已卸下，腰佩和背负装备保留。

2026-10-27 臀胯轮廓修复：完整透明部件原件与绑定遮罩分开保存，`python scripts/export_complete_cutouts.py <输出目录>` 可导出24人的376张透明原件及棋盘格预览。短衣角色的裤装上部固定跟随腰胯，下部跟随腿骨；腰线外被遮住的角料另存，合并后可恢复完整裤片。恢复后摆与渔人蓑衣，取消统一缩短腰胯片的规则，衣长按角色校准。美术数据版本为7，动作仍只有行走。验证同时检查完整源像素保留、腰胯在行走中的稳定性、关节连接和实际客户端关键帧，记录见 `validation/hip-silhouette-repair-20261027.json`。

双击「演示骨骼系统.bat」可在独立演示存档查看24个人物、行走、左右朝向、成品图对照和骨骼关节。衣橱支持「最终效果对照」「原画叠加」和「查看绑定姿态」。

只改颜色或图案时运行 `python unity/bake_ui.py`（加 `--ui-only` 跳过较慢的舆图），需要 Pillow、NumPy 和 SciPy；`prepare.py` 也会自动调用它。

`UnitySmoke.cs` 仅在显式传入 `-smokeDir` 时运行验收。验收必须同时指定独立 `-saveDir`，会执行交易、战斗、移动、月结、导入和另起世界；不得将正式存档目录传给它。验收结果和渲染截图保存在 `unity/validation/`，具体覆盖和限制见 `VALIDATION.md`。

公开源码不提供作者的旧存档快照，因此验收会明确记录跳过旧档导入往返，其余检查继续执行。`VALIDATION.md` 是历史迁移验收记录，引用的本机日志、摘要与存档不随源码发布；日常回归步骤以贡献指南为准。

## 城中地区与地格起伏

城中桥梁已全部移除，原过河位置采用自然浅滩。浅滩与水面同高，每格消耗2行动力；旧存档自动迁移。成品与检查见 [NO_BRIDGES_VALIDATION.md](../NO_BRIDGES_VALIDATION.md)。

城中地图现已铺满整个游戏窗口，人物名册、设施栏、工具条和底栏悬浮于地图上，小地图位于右上角；收起名册不再改变地图相机。首次进入使用240%视角，「全图」仍保留完整地图总览。当前启动器选择 `NoBridges`；最新素材与布局见 [LIVING_PALETTE_VALIDATION.md](../LIVING_PALETTE_VALIDATION.md)，窗口检查见 [CITY_FULLSCREEN_VALIDATION.md](../CITY_FULLSCREEN_VALIDATION.md)。

城中地图按重要程度分为30×30、20×20，分别有34、134个地点，当前世界的49处主要聚落使用对应布局。地格恢复台地、土石侧面和石阶；水面处于低处，相邻可通行地格最多相差一级，人物、路径与点选随地表抬升。

山水边界、树林和田地按独立存档种子成片生成，街路顺应地形连接设施，替代固定棋盘。不同种子的地貌与高程不同，同一存档读取后不会重排，也不消耗世界推演随机数。

建筑仅加载 `CitySettlements/` 的三种指定素材，分别占1×1、2×2、3×3，完整占地统一为水平地基，不回退到其他建筑图。自然地貌从 `CityBiomes/` 合并库的43种素材中精选28种，复杂景观占4格、简洁地面占1格。新增原图与分类目录保存在 `art/landscape-library-20261027/`，由 `unity/import_landscape_library.py` 导入。每张地图保留一个9格城市、一个4格城镇、两个1格村落；十四门派所在地区额外增加独立9格驻地。原图和导入器位于 `art/settlement-tiles-1-4-9/` 与 `unity/import_city_settlements.py`。

大、中地区默认放大视角；滚轮或工具条可缩放至800%，拖动浏览，「全图」复位。坐标格可开关，多格聚落保留独立地格选择。旧版本1至4存档迁移到对应设施或相邻可达地格，不扣行动力、不推进月份、不新增事件。

构建成品为 `unity/Build/LivingPalette/江湖未央.exe`，根目录启动器按 `unity/Build/active-build.txt` 选择版本。规格、来源与检查见 [LIVING_PALETTE_VALIDATION.md](../LIVING_PALETTE_VALIDATION.md)。

## 皮影缩放与关节连接回归

皮影先记录虚拟画布上的视口，再在布局区域结束后，用单位 GUI 缩放的独立绘制通道渲染。视口保留窗口缩放、留白与布局偏移，部件和骨骼线在同一坐标系内旋转，并受视口裁剪。不能直接在带全局缩放的 IMGUI 面板里逐件调用旋转：这会在大窗口下把肢体与骨骼线移出连接点。

原先只验证了模型骨长，未覆盖绘制后的连接。新的 `PaperRenderSmoke.cs` 会检查绘制矩阵中的实际旋转中心和部件末端，遍历 1280×800、1680×960，覆盖全部皮肤、静态绑定与行走、左右朝向和连续播放，并保存实际客户端截图。运行必须使用独立存档：

```powershell
.\启动Unity版.bat -saveDir "D:\Temp\jianghu-rig-test-save" -paperRegressionDir "D:\Temp\jianghu-rig-test-output"
```

`render-regression.json` 同时记录窗口尺寸、图形旋转中心偏移和皮肤连接端误差；截图与数值检查应一起复核。此检查不推进世界月份，也不发起模型调用。本次重写的记录见 `validation/walk-rig-rewrite-20261027.json`。

十四门派重构的历史构建位于 `unity/Build/SectSystem/江湖未央.exe`。当前源码的入门入口为与该派三品及以上人物对话，在「互动」栏选择「拜入门派」，消耗4行动力，不要求在山门；门派页只保留捐助和辞门，二者仍须身处驻地。现有门派差事及NPC自动差事已移除；旧贡献、账目和年谱保留。NPC人物卷中的求师入口已删除，求取秘籍统一从对话「修习 → 请教」办理。历史验证见 [SECT_SYSTEM_VALIDATION.md](../SECT_SYSTEM_VALIDATION.md)。

门派人士现统一一至九品，各派采用自己的九级称谓。最新构建为 `unity/Build/SectNineGrades/江湖未央.exe`；完整晋升规则与验证见 [SECT_NINE_GRADES_VALIDATION.md](../SECT_NINE_GRADES_VALIDATION.md)。
