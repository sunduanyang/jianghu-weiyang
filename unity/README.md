# 江湖未央 · Unity 版

Unity 6000.6.7f1 原生 Windows 客户端，项目目录是 `JianghuUnity/`。安装 Python 3.12+，在 Unity Hub 添加该目录，打开 `Assets/Scenes/Jianghu.unity`，按播放即可运行。默认安装路径也可双击项目根目录的 **用Unity打开.bat**。Python 不在 PATH 时，在启动编辑器前设置 `JIANGHU_PYTHON` 为其完整路径。

公开源码已包含美术、地图纹理和 `.meta` 文件；不包含作者存档、模型、Unity 缓存、Windows 成品或 Python 二进制运行时。无需重新生成资源即可开始修改。**启动Unity版.bat** 用于运行自己构建出的 Windows 程序；如果构建时选择附带 Python，成品无需另外安装 Python。

Unity 负责原生窗口、交互、舆图、城内地图和皮影关节动画；原有 Python 规则引擎作为随游戏启停的本机进程运行。没有嵌入网页，也没有重写一套简化社会规则。运行不需要联网或下载 Unity 商店插件。

## 存档

公开源码首次启动会创建新的800人世界，保存在 `%USERPROFILE%\AppData\LocalLow\JianghuStudio\江湖未央 Unity\Saves`。后续继续这个独立世界。原项目 `data/` 不会被 Unity 写入。作者本地保留的迁移快照只在本机使用，不随仓库公开。

「存档设置」显示实际使用的完整数据库路径，也能打开存档目录。导入旧存档时用 SQLite 在线备份创建新副本；当前 Unity 世界和原始存档均保留。原世界在本次快照之后发生的新变化需重新导入。新世界同样另存文件。

每次新会话默认关闭 AI。需要时先启动原项目的 **启动本地模型.bat**，再在 Unity 的「本地模型」页启用；本地模型文件没有重复复制。规则快进始终跳过模型调用。

Windows 程序可选择附带私有 CPython 运行时，不安装系统服务。Unity 退出或结束播放会通知本次引擎保存并退出；引擎另监测父进程退出。它使用临时本机端口和每会话凭据，避免接入原网页服务。

本机的 Unity DX12 初始化曾出现原生崩溃，项目构建和启动入口已固定使用 Direct3D11。编辑器入口会自动打开主场景。

## 继续开发和构建

主要脚本位于 `Assets/Scripts/`：`JianghuApp.cs` 是界面入口，`WorldUI.cs` 管理双层地图和寻路，`Panels.cs` 管理玩法面板，`PuppetStudio.cs` 驱动皮影关节，`GameClient.cs` 管理请求和进程。共享规则的源文件是仓库根目录的 `jianghu/`，`Assets/StreamingAssets/Backend/jianghu/` 是其同步副本。

修改共享规则后运行 `python unity/prepare.py --backend-only` 同步到 Unity 并一起提交。仅修改 C# 界面或场景时无需同步。`prepare.py` 不会默认复制本机存档；作者确需迁移本机旧档时可显式传入 `--include-local-save`，得到的数据库继续由 Git 忽略。

编辑器菜单 **江湖 / 构建 Windows 游戏** 会生成 `unity/Build/江湖未央.exe`。也可关闭这个项目的编辑器后运行 `构建Unity版.ps1`；自定义 Unity 安装路径使用 `-EditorPath`。默认构建只同步规则，不重新生成美术。需要可独立运行的成品时，先执行 `python unity/prepare.py --bundle-python`，或给构建脚本传入 `-BundlePython`。

重生成资源需要 `python -m pip install -r requirements-dev.txt` 与 `npm ci`，再执行 `python unity/prepare.py` 和 `node unity/bake_puppets.cjs`。完整贡献步骤见根目录 [CONTRIBUTING.md](../CONTRIBUTING.md)。

## 界面布局：仿《太吾绘卷》的深色界面

整体是深色的墨色底子配灯火色，布局参照《太吾绘卷》：

- **天下 / 城中**：舆图和城中图铺满全屏，界面浮在四周。顶栏正中是年月和推演状态，两侧是银两、行动力、声望、武学、体力和在世人口等数值；左栏是名册，分「人物 / 此地 / 地区」三页，可以收起；右上是行旅手记，下面是所选城镇（或城中设施）的详情卡。底栏左边站着主角的皮影立像（还没立主角时是剪影），正中的金色月盘是「结束本月」，盘上显示剩余行动力，没有主角时改为推演一月；两侧是人物、行囊、功法、势力、年谱、皮影和推演七个圆形按钮；右下角的圆盘在「天下」和「城中」之间切换。
- **书页**：人物、行囊、功法、势力、年谱、皮影、本地模型和存档设置都打开为全屏页面，左上角是大字标题，右上角关闭，底部是一排页签，选中的页签是一笔朱红。人物页有圆环头像、基本信息、心性和八个分页的详情。
- **对话**：在人物页点「拜访 / 赠银 / 交谈」进入，左右是双方立像，中间是场景图、对方的念白和编号选项（数字键 1、2 和 Esc 也可以用）。
- **演武**：切磋时，两个人在山水幕布上以现有皮影对阵，间距随身位距离变化。顶部显示气血、内力、架势、脚力与积式；中央显示对方已定意图、运功和受击反馈；底部为行招、六格功法槽、拆招记录与结算。

新约战以空格开始／暂停，可选1／2／3倍速。A／D进退，1／2／3普攻，Q W E Z X C释放装配功法，G架招、F拆招、R调息。运行时自动普攻并继续运功，暂停时仍可逐拍行动。关闭战场或窗口失去焦点会暂停。强招先付出内力与式，再运功1–2拍；出手时重新检查距离，破势可中断。旧战局沿用旧规则，新约战启用积式和运功规则。详细数值与兼容边界见根目录 README 的武学部分。

皮肤代码在 `Assets/Scripts/Theme.cs`（字体、样式、顶栏、底栏、书页框和转场），全屏场景在 `Assets/Scripts/Screens.cs`（人物、对话、演武），舆图和城中图在 `WorldUI.cs`。纹理全部由 `unity/bake_ui.py` 程序生成，固定随机种子，可反复重跑；字体是思源宋体（Noto Serif CJK SC）的子集，由 `unity/build_fonts.py` 生成，许可证见 `Assets/Resources/Fonts/LICENSE-OFL.txt`。字库缺字时，Unity 会退回系统里的微软雅黑或宋体。

山海舆图是绢本画法：`Map/atlas_base.png` 是海面晕染与纸本陆地，`Map/atlas_ink.png` 是海岸墨线、水纹、河流和青绿山形；两者之间按当前归属给各辖区上水彩。全屏时整张图压暗，像灯下看的旧绢图，城镇名用深色名牌。山脉、沙漠、草原和林海的位置是按经纬度手工概括的示意，不是测绘数据。名册与人物页的头像取自当前皮影皮肤的原始头茬，与对话及战斗中的角色形象保持一致。

## 城中小地图

城中图使用原创青绿菱格地形、立体山林、连接街道与木桥，以及15种独立设施图形。各城继续使用原有固定布局，山水、街巷、设施位置和行动力费用不因美化而改变。重生成资源可单独运行 `python unity/bake_city.py`，完整 `prepare.py` 也会生成这些纹理。

- 滚轮或顶部按钮缩放，按住地图空白处拖动浏览；「全图」和左下角总览可复位视野。
- 单击地格或名牌选择目的地，悬停查看地形与路线费用。金色虚线显示最低行动力路径，超出本月余量时变为朱红；水、山、城垣显示阻断原因。
- 「可达范围」以绿框显示主角本月能走到的格子；「名牌」「地格」可分别开关。右侧设施名录支持筛选，选择名录条目会定位该设施。
- 主角所在地可按「行走至此」执行原有移动，或用方向键逐格走；远方地图只供游览。主角定位、设施服务、查看人物和城外行路继续沿用现有接口。

原生地图验收可用 `-citySmokeDir <输出目录> -saveDir <独立测试存档目录>` 启动构建成品，验证24城的前后端路线费用、缩放坐标、实际移动并保存截图。此模式会在指定测试存档创建主角和行走，不得传入正式存档目录。

## 共用皮影骨骼与皮肤

`art/puppet-cast-24/` 保存 24 套原始皮肤、405 个独立 PNG 部件、透明总图、生成提示词和来源摘要，`index.html` 可离线浏览。素材与程序一并公开，不需要本机 `output/` 目录。

`unity/paper-rig.json` 是骨骼长度、关节层级和动画关键帧的唯一配置。七种通用动作包括静立、行走、交谈、进招、招架、受招和收势。`PaperRig.cs` 以相同前向运动学计算所有皮肤，动作切换先混合关节参数再解算，保持骨长；朝向在整体绘制时镜像，不重新采样动画。`PaperCast.cs` 负责统一形象匹配、图集缓存、原始头茬头像、部件层次与配饰挂点，地图主角、人物页、对话和演武共用它。战斗动画读取实际行动、命中及胜负记录，外观不改变规则数值。

`python unity/bake_paper_cast.py` 从原始 RGBA 部件机械打包运行图集，并从铜铆钉校准绑定锚点，检查像素保真、透明通道和素材摘要。生成结果在 `Assets/Resources/PaperCast/`，已连同 `.meta` 入库；安装开发依赖后才能重生成，直接打开源码工程不需要重生成。新增皮肤使用相同 16 个核心部件标识、独立配饰和清单，添加到 `cast-spec.json` 后重新打包；无需为该皮肤另写动画。

「皮影衣橱」可切换全部皮肤、七种动作和左右朝向，可播放、拖动动作进度、显示骨骼与关节，也可查看全部皮肤的组装总览。原矢量试样保留为历史资源及几何回归参考，不再充当人物头像和演武中的黑影。

验证包括 `python -m unittest discover -s tests -v` 的素材契约检查，以及 Unity 独立测试存档中的逐皮肤骨长、实际人物页、对话、左右朝向总览与战斗截图。现有配饰是皮肤构成，尚未实现任意装备换装、布料物理或碰撞驱动动画。

只改颜色或图案时运行 `python unity/bake_ui.py`（加 `--ui-only` 跳过较慢的舆图），需要 Pillow、NumPy 和 SciPy；`prepare.py` 也会自动调用它。

`UnitySmoke.cs` 仅在显式传入 `-smokeDir` 时运行验收。验收必须同时指定独立 `-saveDir`，会执行交易、战斗、移动、月结、导入和另起世界；不得将正式存档目录传给它。验收结果和渲染截图保存在 `unity/validation/`，具体覆盖和限制见 `VALIDATION.md`。

公开源码不提供作者的旧存档快照，因此验收会明确记录跳过旧档导入往返，其余检查继续执行。`VALIDATION.md` 是历史迁移验收记录，引用的本机日志、摘要与存档不随源码发布；日常回归步骤以贡献指南为准。
