# 江湖未央 · Unity 版

Unity 6000.6.7f1 原生 Windows 客户端，项目目录是 `JianghuUnity/`。安装 Python 3.12+，在 Unity Hub 添加该目录，打开 `Assets/Scenes/Jianghu.unity`，按播放即可运行。默认安装路径也可双击项目根目录的 **用Unity打开.bat**。Python 不在 PATH 时，在启动编辑器前设置 `JIANGHU_PYTHON` 为其完整路径。

公开源码已包含美术、地图纹理和 `.meta` 文件；不包含作者存档、模型、Unity 缓存、Windows 成品或 Python 二进制运行时。无需重新生成资源即可开始修改。**启动Unity版.bat** 用于运行自己构建出的 Windows 程序；如果构建时选择附带 Python，成品无需另外安装 Python。

Unity 负责原生窗口、交互、舆图、城内地图和皮影关节动画；原有 Python 规则引擎作为随游戏启停的本机进程运行。没有嵌入网页，也没有重写一套简化社会规则。运行不需要联网或下载 Unity 商店插件。

## 存档

公开源码首次启动会创建新的800人世界，保存在 `%USERPROFILE%\AppData\LocalLow\JianghuStudio\江湖未央 Unity\Saves`。后续继续这个独立世界。原项目 `data/` 不会被 Unity 写入。作者本地保留的迁移快照只在本机使用，不随仓库公开。

「存档设置」显示实际使用的完整数据库路径，也能打开存档目录。导入旧存档时用 SQLite 在线备份创建新副本；当前 Unity 世界和原始存档均保留。原世界在本次快照之后发生的新变化需重新导入。新世界同样另存文件。

每次新会话默认关闭 AI。需要时先启动原项目的 **启动本地模型.bat**，再在 Unity 的「本地模型」页启用；本地模型文件没有重复复制。规则快进始终跳过模型调用。

Windows 程序可选择附带私有 CPython 运行时，不安装系统服务。Unity 退出或结束播放会通知本次引擎保存并退出；引擎另监测父进程退出。它使用临时本机端口和每会话凭据，避免接入原网页服务。

本机的 Unity DX12 初始化曾出现原生崩溃，项目构建和启动入口已固定使用 Direct3D11。编辑器入口会自动打开主场景。

## 继续开发和构建

主要脚本位于 `Assets/Scripts/`：`JianghuApp.cs` 是界面入口，`WorldUI.cs` 管理双层地图和寻路，`Panels.cs` 管理玩法面板，`PuppetStudio.cs` 驱动皮影关节，`GameClient.cs` 管理请求和进程。共享规则的源文件是仓库根目录的 `jianghu/`，`Assets/StreamingAssets/Backend/jianghu/` 是其同步副本。

修改共享规则后运行 `python unity/prepare.py --backend-only` 同步到 Unity 并一起提交。仅修改 C# 界面或场景时无需同步。`prepare.py` 不会默认复制本机存档；作者确需迁移本机旧档时可显式传入 `--include-local-save`，得到的数据库继续由 Git 忽略。

编辑器菜单 **江湖 / 构建 Windows 游戏** 会生成 `unity/Build/江湖未央.exe`。也可关闭这个项目的编辑器后运行 `构建Unity版.ps1`；自定义 Unity 安装路径使用 `-EditorPath`。默认构建只同步规则，不重新生成美术。需要可独立运行的成品时，先执行 `python unity/prepare.py --bundle-python`，或给构建脚本传入 `-BundlePython`。

重生成资源需要 `python -m pip install -r requirements-dev.txt` 与 `npm ci`，再执行 `python unity/prepare.py` 和 `node unity/bake_puppets.cjs`。完整贡献步骤见根目录 [CONTRIBUTING.md](../CONTRIBUTING.md)。

## 界面风格：戏与书

界面分两种模式。**戏**是事情发生的地方（山海舆图、城中行旅、功法演武、皮影换装），中间区域是木框围着的一块透光皮影幕布；**书**是查阅的地方（行囊货栈、天下势力、世界年谱），中间区域是印本书页的双线版框。左右两栏的名册和人物档案始终是书页。两种模式之间切换时，戏有开幕动画，书有翻页动画。本地模型和存档设置放在页签栏右侧的小链接里。

皮肤代码在 `Assets/Scripts/Theme.cs`（字体、九宫格样式、面板、页头页签和转场）。纹理全部由 `unity/bake_ui.py` 程序生成，固定随机种子，可反复重跑；字体是思源宋体（Noto Serif CJK SC）的子集，由 `unity/build_fonts.py` 生成，许可证见 `Assets/Resources/Fonts/LICENSE-OFL.txt`。字库缺字时，Unity 会退回系统里的微软雅黑或宋体。

山海舆图改为绢本画法：`Map/atlas_base.png` 是海面晕染与纸本陆地，`Map/atlas_ink.png` 是海岸墨线、水纹、河流和青绿山形；两者之间按当前归属给各辖区上水彩（`Map/cell-*.png` 在边缘加深，像颜料在纸上积在边缘）。驿道是赭色虚线，航路是青色长虚线，城镇是印章式标记，首府用朱印。山脉、沙漠、草原和林海的位置是按经纬度手工概括的示意，不是测绘数据。

只改颜色或图案时运行 `python unity/bake_ui.py`（加 `--ui-only` 跳过较慢的舆图），需要 Pillow、NumPy 和 SciPy；`prepare.py` 也会自动调用它。

`UnitySmoke.cs` 仅在显式传入 `-smokeDir` 时运行验收。验收必须同时指定独立 `-saveDir`，会执行交易、战斗、移动、月结、导入和另起世界；不得将正式存档目录传给它。验收结果和渲染截图保存在 `unity/validation/`，具体覆盖和限制见 `VALIDATION.md`。

公开源码不提供作者的旧存档快照，因此验收会明确记录跳过旧档导入往返，其余检查继续执行。`VALIDATION.md` 是历史迁移验收记录，引用的本机日志、摘要与存档不随源码发布；日常回归步骤以贡献指南为准。
