# 后台思考瘦身与人生转折验收（2026-10-29）

目标：没有和玩家打过交道的 NPC，也能在人生的要紧关头由模型来想；同时让每次思考快得多。

## 一、后台思考瘦身

此前每次后台思考，发给模型的资料中位数约 1.49 万字符（1800 人世界，推演 4 个月后，抽查 80 名成年人），已接近 8192 的上下文上限。要求输出的内容有短期计划、理由、一年方针、经历反思和长期筹划，约 280 个 token，普通人物一次约 9–11 秒。

现在，没有与玩家来往、也非高品阶或在任官员的人（思考级别为「日常思考」）改用**简短请求**：

- **输入**（`ai.lean_wire`）：只给这次决定需要的资料：
  - 本人概况（年龄、性别、营生、家资、体力、性格、心愿、官职）；
  - 职责、手上计划的状态与阻碍、本人近况（在忙的事、烦心事、在意的人、最近经历、家人）；
  - 三段记忆；
  - 至多 10 个候选行动；
  - 可选心愿、可立的长期筹划；
  - 若有人生转折，附上转折。

  中位数降到约 **1900 字符**（同样抽查 80 人，最多约 2400），是原来的约八分之一。系统提示从约 1000 字缩到约 350 字。
- **输出**（`ai.lean_schema`）：
  - 眼下的行动、心愿、长期筹划各一个编号；
  - 一句二十字以内的心声；
  - 若是人生转折，再加一个面对方式。

  输出上限 120 个 token（配置项 `lean_tokens`），实际约几十个。
- 回答经 `ai.expand` 展开成完整提案，交给原有的 `apply_decision` 做同样的校验：行动、心愿、筹划都要合法，处境改变则整份拒绝。短计划只有这一步，不写一年方针，也不做性格反思。心声写进计划理由。
- 与玩家有来往的人、高品阶人物和在任官员，仍用原来的完整请求和两轮深思。

**估计**：输入缩到约八分之一，输出缩到几分之一，一次简短决定应能从约 10 秒降到 2 秒左右。这只是按 token 数推算的，实际速度需要在本机实测。模型页新增「简短决定」计数，可以对照。

## 二、人生转折（新模块 `jianghu/turning.py`）

不再只靠按顺序轮换，而是在人生转折发生时，给当事人记下一个待想的转折：

| 事件 | 当事人（分量） |
| --- | --- |
| 亲人亡故 | 继承的亲人（1.0） |
| 成亲 | 双方（0.9） |
| 被背叛 | 受害者（0.9）、背叛者（0.6） |
| 获得官职 / 被推举主持门派 | 本人（0.8） |
| 官府判决 | 被判者（0.8）、受害者（0.6） |
| 比武 | 落败者（0.7）、胜者（0.5） |
| 生儿育女 | 父母（0.7） |
| 被勒索、被造谣且真相大白 | 受害者（0.6）；造谣者（0.5） |
| 提亲被拒、离开门派 | 本人（0.6） |
| 偷窃败露 | 受害者（0.5）、窃贼（0.4） |
| 心愿达成、放下旧怨 | 本人（0.5） |

- 未成年人不记。每人最多同时记两个，保留分量最重的；三个月内没轮到就作废，规则照常运行。
- **排队**：后台每次排程，先给转折点，但最多占可用名额的一半，其余仍按原来的轮换。转折点按分量排序：与玩家同城加 0.3、同国加 0.15，每晚一个月减 0.1。同一个人每月最多尝试一次。
- **思考转折时**，心愿可以在全部可选心愿里重新选，长期筹划也随之重列。模型要从与这件事相符的面对方式中选一个：

  | 面对方式 | 效果 |
  | --- | --- |
  | 咬牙挺过 | 心情略好，不再急于改变 |
  | 消沉一阵 | 心情变差，更想找人说话 |
  | 记恨在心 | 复仇之心 +10，怒气 +6 |
  | 放下宽恕 | 复仇之心 −15，怒气 −10，对加害者情分 +5 |
  | 欣喜振奋 | 心情变好 |
  | 痛定思痛 | 下次更急于重新考虑人生 |
  | 随遇而安 | 无 |

  受害者可选：记恨、宽恕、挺过、痛定思痛。痛失亲人可选：消沉、挺过、痛定思痛。其余身份各有相符的选项。
- 心声写进此人对该事件的记忆，并记入「人生转折」履历。NPC「行事与打算」页显示尚在心头的转折和最近三次的选择与心声。
- 选了不在范围内的面对方式时整份拒绝。旧格式的回答没有这一项时，其余照常采用，转折留待以后再想。

**数量**：1800 人世界每月新增约 220 个转折，其中分量 0.8 以上的约 70–90 个。本机每个游戏月能处理多少，取决于实际速度；按分量排序可以保证最要紧的先想。

## 三、模型页

新增「简短决定 / 人生转折已想 · 待想」三项计数。

## 验证

- `python -X utf8 -m unittest discover -s tests -q`：661 项通过，其中新增 `tests/test_lean_thinking.py` 5 项。覆盖：
  - 日常人物走简短请求：资料不到 5000 字符、不到完整资料的一半，一次请求，输出上限 120；深思人物仍走完整请求；
  - 简短回答经同样校验后采用，空回答被拒；
  - 转折只记给当事的成年人，保留分量最重的两个，三个月后作废；
  - 转折点优先排队但至多占一半名额，处理后写入履历和心声；
  - 宽恕降低复仇之心、提高对加害者的情分；不合范围的面对方式不改变任何状态；旧格式回答保留转折待想。
- `tests/test_richer_lives.py` 中「完整请求不含规则推荐」一项，改为显式检查完整请求（日常人物现在走简短请求）。
- 这里没有显卡和本地模型，实际提速需要在本机实测。C# 只做了括号配平检查。
