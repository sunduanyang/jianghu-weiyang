# 人物来访验收（2026-10-29）

此前 NPC 从不主动来找玩家，只等玩家上门。现在认识玩家的人会为真实的缘由登门。规则在新模块 `jianghu/visits.py`。

## 谁会来、为什么来

每月月末，规则查看玩家所在城镇里与玩家有往来的人（陌生人不会来），从真实处境中找来访的理由：

| 来访 | 条件 | 玩家可以 |
| --- | --- | --- |
| 师父召见 | 他是玩家的师父，每季度一次 | 恭敬听训（1 行动力，情分 +3、信任 +2）/ 推说有事（−2 / −1） |
| 上门寻衅 | 对玩家情分 ≤ −30、刚烈 ≥ 55，且正在气头上 | 赔礼二两（+6 / +3）/ 好言相劝（+2）/ 针锋相对（−4 / −2，对方更怒） |
| 登门道谢 | 两个月内玩家接济过他或送过礼 | 受了这份谢意（+2 / +2）/ 谦让不受（+1 / +3） |
| 登门求助 | 对玩家情分 ≥ 20，自己家资不足 12 银 | 借他四两（交付 4 银，记下人情，+4 / +3）/ 婉言推辞（−2） |
| 好意示警 | 对玩家情分 ≥ 30，他认识的同城某人对玩家怀恨 | 谢他提醒（+2 / +2）/ 不以为意（−1） |
| 相邀叙旧 | 对玩家情分 ≥ 40 | 应邀前往（1 行动力，+4 / +2）/ 改日再聚（−1） |

- 每月最多两人来访，按上表从上到下优先；
- 同一个人三个月内最多来一次，同一缘由六个月内不重复；
- 来访等到下月底，过期作废；
- 登记时写一条「人物来访」事件，记下缘由；
- 生成过程确定，不消耗随机数。

## 模型做什么

- 规则登记来访时，先给出一句写明缘由的说明。模型启用后，后台为每个来访者写开口的话，同一时间只写一份。
- 模型拿到的资料：来访缘由、玩家可以作出的回应、此人的近况和口吻，以及他对玩家的看法。
- 模型用一到两句话说明来意，口吻按此人的口吻卡，可以带上他自己的处境和心情。
- 校验：
  - 不得出现资料以外的人名；
  - 数字只能是二或四（赔礼和借银的数额）；
  - 要含中文，且不得出现系统字样。

  不合格最多重试两次，之后沿用规则说明。
- 玩家作答后，来访者照常给出一次人物回应：答应了就从感激一类的态度里选，拒绝或针锋相对就从芥蒂、怀恨一类里选。

## 结算

- 新接口 `/api/visit`：先校验版本、月份、来访状态、来访者是否仍在世且在玩家所在城镇、银两和行动力，全部通过后才结算；任何一项不通过都不改变存档。
- 结算内容：
  - 交付银两（借出的四两记作对方欠下的人情）、扣行动力、调整关系；
  - 针锋相对会让对方更怒；
  - 赔礼或好言相劝会稍稍平息对方的复仇之心。

  结算写一条「回应来访」事件，以来访事件为起因。

## 界面

主角页顶部新增「有人来找你」：显示来访者、缘由和开口的话，下面是回应按钮（银两或行动力不足时灰显），另有「见见此人」按钮。来访者若已离开，会提示等他回来再答复。模型页的参与度统计里新增已写好的来访开口数（`visit_openings`）。

## 验证

- `python -X utf8 -m unittest discover -s tests -q`：654 项通过，其中新增 `tests/test_visits.py` 6 项。覆盖：
  - 真实缘由带来来访，陌生人不来，每月只登记一次，不消耗随机数；
  - 每月至多两人，召见与寻衅优先，同一人不会接连来，过期作废；
  - 回应按选项结算；非法回应、过期版本、重复回应都不改变存档；回应后由来访者作人物回应；
  - 来访者离开或银两不足时不能作答；
  - 模型以来访者口吻写开口的话，编造人名或数额的会被拒；
  - 月末推演会登记来访。
- 这里没有显卡和本地模型，真实效果仍需在本机试玩确认。C# 只做了括号配平检查。
