# 关节绑定

「系统 → 关节绑定」把 AI 生成的拆件图手动绑成可动的皮影，并可用于切磋。

## 用法

1. **从拆件图新建**：把 PNG 放进「打开拆件图文件夹」打开的目录（成品为 `persistentDataPath/RigSources`），点它即按透明区域自动切块，编号数字等小块会丢掉。附带的 `示例拆件图.png` 可直接试；纯色背景也能切。
2. **分配部位**：左栏选部位（躯干、头、前后摆、两侧大臂 / 小臂 / 手、两侧大腿 / 小腿 / 脚；颈可不用），再点下方拆件。
3. **点关节**：可以先点「自动猜关节」（或左栏「补猜空部位」一次猜完所有还没点的部位），它按拆件形状估出关节位置，在示例上中位误差约为拆件尺寸的 4%，再拖动微调即可。也可以直接在中间大图上点。**起点**是这块接到上一级的位置，**终点**是下一块接上来的位置；躯干另有两肩、两髋（髋可不标，默认在腰）。手可加**握点**，决定兵器握在哪。拖动圆点微调，Ctrl+Z 撤销；滑杆调每个关节的转动范围。
4. **检查**：右侧「原样拼合」按各块原始角度拼起来，肩、肘、髋、膝的圆点应落在布料重叠处的中心；「提线悬挂」「落地」是布娃娃，可拖动任意部位。下方列出与切磋骨架的比例差，超过 15% 标红。
   「切磋预览」让两人按切磋骨架的出场姿势对面站，画法与切磋完全相同；下方列出每个关节的接缝（上一块的接口与下一块起点相距多少原画像素），露在外面且超过 20 的标红，被衣摆或身体挡住的会注明。「接缝补偿」允许躯干和四肢按骨长等比微缩放（最多 ±20%），不拉伸。
5. **保存、设为外观**：编辑器里保存到 `Assets/StreamingAssets/Rigs/<名称>/`（随项目提交、随构建发布），成品保存到 `persistentDataPath/Rigs`。「设为切磋外观」后，切磋中你的角色使用这套绑定；「设为对手外观」让对手使用某一套，可以与你不同；两人用同一套时对手略偏冷色以便区分。

原画人物面朝左时勾「原画面朝左」：切磋里的翻转、关节限位和自动猜关节都会随之调整。

网页版绑定台导出的 JSON 可用「读入网页版 JSON」从剪贴板读入。附带的「示例少年」已绑好。

## 切磋中的绘制

每块拆件的起点放在对应物理骨骼的关节上，沿骨骼方向旋转；全身只用一个由最小二乘求出的比例，**不拉伸**（开了接缝补偿时，躯干和四肢各自等比微缩放）。碰撞、质量和伤害仍由原物理骨架决定。

绘制由 `Rigging/RigPoseRenderer.cs` 完成，它只需要每个部位的骨骼两端，不依赖物理引擎。切磋一侧（`PhysicsCombat/DuelBoundRig.cs`）只负责报告骨骼两端；换物理引擎（例如 Physics Core 2D）时，只要 `Limb` 仍提供 `A`、`B`、`length`，并改写其中的 `AnkleWorld`，绑定就不必再动。

其它验收脚本运行时不使用玩家选的外观，保证它们看到的仍是原来的人物。

## 拆件图要点

- 关节处两头画成圆头，互相重叠，弯曲时才不露缝。
- 每块只画自己那部分，例如大腿只画到膝盖，不要连小腿一起画。
- 侧身躯干不带袖子。

## 数据格式

`rig.json`（`format: jianghu-joint-rig`, `version: 2`，另有 `facing`、`fit_tolerance`）：`pieces` 记每块的文件与在原拆件图中的位置；`slots` 记每个部位用哪块、各关节点坐标（拆件自身像素，x 向右，y 向下，人物面朝右）；另有 `draw_order` 与 `limits`。拆件图片存在同目录的 `pieces/`。

## 验收

```
python scripts/prepare_reference_acceptance.py --save-dir output/rig-binder-check/save
江湖未央.exe -rigBinderSmoke <输出目录> -saveDir <工作区绝对路径>/output/rig-binder-check/save
```

检查切图、示例绑定完整、远侧肩位置、自动猜关节的误差、面朝左时左右对称、接缝测量与补偿、木偶拖动与落地不散架、存取一致、绑定台能打开、从正式后端进入切磋、双方确实使用绑定且能保存；结果写入 `report.json` 并附截图。
