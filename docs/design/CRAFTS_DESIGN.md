# 技艺系统

技艺是武学之外和江湖打交道的另一条路：打兵器、治伤、写字。它不另起一套"资质＋造诣"数值树，而是接在现有的营生、物品、物理战斗、交互和门派上，让每门技艺都改变一件玩家摸得到的东西。

第一期已实现锻造、医术、诗书三门，规则在 `jianghu/crafts.py`，测试在 `tests/test_crafts.py`。本文先写已实现的规则，再列后续计划。

## 1. 已定原则

| 问题 | 决定 |
| --- | --- |
| 营生与技艺 | 共用同一个熟练度：匠人即锻造，药师即医术，书生即诗书 |
| 断肢 | 不永久。断离记为"重创"，伤期长，可以治好 |
| 修补 | 不懂锻造只能修到 70 耐久；锻造造诣达 15 才能修满，或请懂锻造的人修 |
| 部位伤与下一场战斗 | 暂不带入。部位伤只影响世界层（营生、旅行）和诊治 |
| 随机 | 锻造火候、墨宝品阶都由种子和新物品编号派生，不消耗世界随机数，可复现 |
| 旧存档 | 无需迁移。没有 `craft` 记录的物品、没有 `parts` 的伤势，行为与以前相同 |

## 2. 造诣

- **NPC**：造诣就是 `career.experience` 中对应职业那一项。`crafts.value(n, 'forging')` 读的就是 `career.experience['匠人']`，`crafts.gain` 调用 `careers.gain`，所以收入、入行门槛、`learn_trade` 和技艺看到的是同一个数。
- **主角**：主角没有营生记录，同一尺度存放在 `player['crafts']['skill']`（0–100）。
- **等级名**：沿用 `careers.LEVELS`，即初入行、熟手（15）、行家（35）、名家（60）、宗匠（85）。
- **实践增长**：`基础值 × (1 − 造诣/120)`，最少 0.05，越精越慢。
- **学艺**：增益 `2 + 师父造诣 × 0.03`，与 NPC 的 `learn_trade` 同式。

## 3. 锻造

**打造**（`POST /api/crafts {operation:'forge', template, temper}`，耗 3 行动力）：

- 可锻造：所有有物理参数的兵器模板。
- 难度按品阶：九品 0，八品 8，七品 18，六品 28，五品 40，四品 52，三品 64，二品 76，一品 85。造诣须达"难度 − 15"。
- 用料：木剑用硬木料，其余用生铁。九、八品 1 份，往上逐步增加，一品 5 份。
- 工费：`2 + (9 − 品阶) × 3` 银。
- 材料来源：先用行囊里的料。不足时，在市集经济中按 0.5 单位散料一份从本地市集购入并计入消耗；市集没货就不能打造。
- 火候：`q = 0.35 + (造诣 − 难度) × 0.012 + 锻铁锤 0.05 ± 0.08 − 手臂骨伤 × 0.15`，限制在 0.05～1。分为粗糙、寻常、精良、上乘、绝品五档。
- 绝品（q ≥ 0.88）声望 +1。

**取向与修正**：修正只存在实例的 `item['craft']['mods']`，`weapons.attributes()` 在模板数值上乘以修正。修正经 `physical_combat.equipment()` 进入战斗包，由 Unity 的 `DuelWeapon.CampaignWeapon` 读取，战斗代码无需改动。

| 取向 | 质量 | 操控 | 压盾 | 耗气 | 其他 |
| --- | --- | --- | --- | --- | --- |
| 重锻 | ×(1.06+0.06q) | ×0.97 | ×(1.04+0.06q) | — | — |
| 均衡 | ×1 | ×(1+0.06q) | — | — | 磨损倍率 1−0.4q |
| 轻锻 | ×(0.95−0.07q) | ×(1.04+0.06q) | — | ×0.95 | — |

- 所有修正限制在 0.85～1.15。
- 杀伤系数最多 +3%。伤害与系数线性相关（参考规则中约为 `16c/15`），锻造修正不超过相邻两品兵器之差。
- 火候低于 0.3 时操控反而下降。
- 售价乘以 `0.7 + 0.6q`。

**修补**：

- 自修：造诣不足 15 时只修到 70 耐久，造诣达到后可修满。耐久已达上限时不再提供修补选项。
- 请人修补（人物交互 · 互动，1 行动力）：对方锻造造诣 ≥ 15。修满你耗损最重的兵器、盾牌或衣甲，优先已装备的。工钱为 `价格 × 损耗 × 0.25 × 1.5`，最少 2 银，全额付给对方，对方自备料并得到锻造经验。

**NPC 铸剑师**：锻造造诣 ≥ 35、家资 ≥ 24 的匠人，每隔一个半年产出期改为打一件兵器，按售价卖给货栈。兵器带"某某所铸"和真实火候。银两在匠人与货栈之间转移，只有炉火工费流出。

## 4. 医术

**部位伤**：抢夺、袭击、门派缉拿结算时（`crafts.settle_battle`），从最终物理快照 `frame.fighters[i].reference.parts` 读取各部位：

| 情况 | 记为 | 伤期（月） |
| --- | --- | --- |
| 部位断离 | 重创 `maimed` | 8 |
| 四肢损失 ≥ 60% | 骨折 `fracture` | 3 + round(程度 × 4) |
| 损失 ≥ 25% | 外伤 `cut` | 1 + round(程度 × 3) |

- 记录写入 `wound.parts`。`wound.remaining` 取原有伤期、旧规则 `2+round(损失×3)` 和各部位伤期中的最大值。
- 切磋不留伤。没有部位快照时，结果与旧规则逐字相同。

**伤势影响**：

- 手臂骨折或重创：匠人、渔人、猎户、农人的产出乘以 `1 − 0.5 × 程度`，经济模式与传统收入都生效；同时降低锻造火候。
- 腿部骨折或重创：NPC 旅行的体力消耗乘以 `1 + 程度`。
- 主角的伤势现在每月减一，期满痊愈（以前不会自行痊愈）。

**诊治**（`crafts.treat`）：

- 体力恢复 `(4 + 医术 × 0.1) × 药力`。
- 疗效 `power = (0.25 + 医术 × 0.006) × 药力`。病势乘以 `1 − min(0.6, power)`；最重的一处伤减去 `power`。
- 骨折和重创须医术 ≥ 25 才能处理，否则只能止痛（伤期减 1）。接骨后骨折转为外伤。程度低于 0.15 的伤处视为痊愈。
- 用金疮药诊治时药力 ×1.3，消耗一份。
- 途径：
  - 人物交互「诊治」（互动，2 行动力）：交情、信任增进，对方欢喜，主角医术增长，对方以"受你诊治的人"身份作出回应。
  - 市井 · 技艺 · 调治（2 行动力）：为自己调治。
  - NPC 求医：药师按自己的医术处理部位伤；没有部位伤时仍按旧规则。

**制药**：养心丸须医术 15，金疮药无门槛。医术高于 0 时，药物会带上 `craft.potency = 1 + 医术 × 0.004`（最高 1.4），服用时体力恢复相应增加。

## 5. 诗书

**墨宝**（`POST /api/crafts {operation:'compose', title?}`，2 行动力、1 银纸墨）：

- 品阶：`诗书造诣 ± 10` 分档，可得九品习字诗笺至三品传世法帖。
- 题目：可自拟，1 至 12 字，会过滤书名号和控制字符；不填则从固定词表中取。
- 新物品类别"墨宝"只由人写成，货栈开张和目录扩充都不会进货。

**赠礼**：主角赠送墨宝时，交情增量为原来的 `min(12, 2 + 价格/10)` 乘以欣赏度，亲笔再加 1，上限 16。

```
欣赏度 = 0.6 + 对方诗书/100 + (对方 tradition 观念 − 50)/200 + (书生或艺人 ? 0.3 : 0)，限制在 0.3～1.8
```

事件文字写明"对方细细品读，爱不释手 / 欣然收下 / 似乎不甚在意"。现有的 LLM 回应管线据此让对方开口；模型关闭时仍是规则结果。

## 6. 接口与界面

| 接口 | 用途 |
| --- | --- |
| `GET /api/crafts` | 造诣列表、锻造选项及不满足原因、墨宝和调治条件、药方门槛、修补上限、主角部位伤 |
| `POST /api/crafts` | `forge` / `compose` / `treat_self`；条件全部校验后才改动状态，须先暂停江湖 |
| `POST /api/items {operation:'craft'}` | 保留，制药加上医术门槛与药力 |
| 人物交互 | 新增「学艺」（修习）、「诊治」（互动）、「请人修补」（互动），由后端驱动自动出现 |

Unity 改动：

- 「市井」原「制药」分页改为「技艺」，下设造诣、锻造、题字、制药、调治（`CraftsPanel.cs`）。
- 物品详情显示火候或所铸者，例如"某某所铸 · 重锻 · 上品火候"。
- 同模板但火候不同的物品不再合并显示。

## 7. 验证

- `python -m unittest discover -s tests -v` 全部通过，其中包括 `tests/test_crafts.py`。
- 因交互由 12 项增至 15 项、修补上限改为 70，已相应更新 `test_player_interactions`、`test_interaction_conversation`、`test_items`、`test_weapons`。
- 修改规则后已运行 `python unity/prepare.py --backend-only`，同步副本已一并提交。
- Unity 客户端须在 Windows 编辑器中编译，并从正式人物交互进入抢夺或袭击，验收部位伤写入、读档、诊治和锻造修正。

## 8. 后续

1. 部位伤带入下一场非切磋战斗：战斗包加 `part_health`，Unity 建 rig 时按 `上限 × (1 − 程度 × 0.7)` 设部位初始血量。
2. 织锦：用 Unity 已支持的 `armor_layers` 定义按部位覆盖的护具。
3. 厨艺：烹制现有的九品食物。
4. 毒术：淬毒于刃，命中部位后扩散。
5. 品鉴：交易时看穿火候与真伪。
6. 门派技艺差事：在 `sect_life.board` 增加"上缴兵器""为门人诊治"。
7. 音律、书画沿用诗书的作品机制；老伤可作为治好后的永久小幅减益另行设计。
